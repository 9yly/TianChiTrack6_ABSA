# 中文电商化妆品评论 ACOS 四元组抽取技术方案（MethodsV2）

## 1. 方案动机（Motivation）

中文电商化妆品评论文本具有口语化、表述灵活、属性-观点关联隐蔽等特点，传统规则或单一模型微调通常面临三类挑战：

- **长尾场景适配不足**：如小众功效评价、隐晦情感表达。
- **隐式属性配对困难**：属性词未显式出现（aspect 为空或用 `_` 表示），但存在观点词时，配对准确率偏低。
- **类别与极性易受语境干扰**：如“味道特别”可能对应正面/负面，需要结合相似案例辅助判断。

为解决上述问题，本方案采用“**模型微调 + RAG 增强**”的混合架构：

1. 通过微调让模型掌握化妆品领域 ACOS 四元组抽取的基础逻辑与输出格式。
2. 通过 RAG 检索相似训练样本作为 few-shot 提示，补充语境参考。
3. 最终提升抽取的 **准确度、鲁棒性与场景适配能力**。

## 2. 核心技术架构

本方案由两部分组成：

- **模型微调（LoRA）**：建立稳定的结构化输出能力。
- **RAG 增强系统**：检索相似案例，为推理提供高质量 few-shot 示例。

### 2.1 模型微调

- **基础模型**：`Qwen/Qwen2.5-32B-Instruct`
- **微调方式**：LoRA（Low-Rank Adaptation）轻量化微调（本地训练）
- **微调目标**：
	- 学会 ACOS 四元组定义（属性词、观点词、类别、极性）
	- 适配电商口语化表达
	- 强化结构化 JSON 输出稳定性

### 2.2 RAG 增强系统

RAG 的目标是为模型提供“**相似案例参考**”，通过检索训练集中语义相近的样本，辅助判断：

- 属性-观点配对
- 类别划分
- 情感极性

从而弥补单一微调模型在长尾场景上的覆盖不足。

#### 2.2.1 核心流程

RAG 增强分为 **检索 → 重排序 → 示例格式化** 三个阶段：

**阶段一：BM25 初步检索（召回）**

- **算法**：BM25（基于 TF-IDF 的相关性度量）
- **逻辑**：以测试样本评论文本为 query，从训练集召回 Top-20 候选（包含标注四元组）
- **作用**：快速过滤无关样本，为后续精排提供候选池

**阶段二：Reranker 语义重排序（精排）**

- **模型**：`BAAI/bge-reranker-v2-m3`
- **部署**：Ollama 本地部署（提升稳定性与吞吐）
- **逻辑**：对 BM25 召回的 20 条候选按深层语义相似度排序，保留 Top-5
- **作用**：减少 BM25 词面匹配带来的噪声，提高 few-shot 示例的语义相关性

**阶段三：示例格式化（few-shot 提示）**

- **格式标准**：`评论文本 + 标准四元组 JSON`
- **作用**：降低模型理解成本，确保参考案例可直接复用到 prompt 中

示例（单条 few-shot）：

```text
评论文本: 物流很快，包装也不错，用着挺好的
{"quadruples":[{"aspect":"物流","opinion":"很快","category":"物流","polarity":"正面"},{"aspect":"包装","opinion":"不错","category":"包装","polarity":"正面"},{"aspect":"_","opinion":"挺好的","category":"使用体验","polarity":"正面"}]}
```

## 3. 系统提示词（System Prompt）

为确保输出严格符合提交规范，使用强约束 System Prompt：

```text
你是一个专业的中文电商化妆品评论观点四元组抽取助手。
任务：给定一条化妆品电商评论文本，抽取其中所有的观点四元组（AspectTerm, OpinionTerm, Category, Polarity），即 ACOS 四元组。
严格遵守以下规则：
1. 输出唯一JSON：{"quadruples":[{"aspect":"...","opinion":"...","category":"...","polarity":"..."}, ...]}
2. quadruples为数组；若没有观点，输出{"quadruples":[]}
3. aspect：若无显式属性词用"_"；原文中出现的需与原文一致，不添加空格
4. opinion：必须是原文中连续片段，保持原字符；无观点则不输出该条四元组
5. category取值仅限：包装、成分、尺寸、服务、功效、价格、气味、使用体验、物流、新鲜度、真伪、整体、其他
6. polarity取值仅限：正面、中性、负面
7. 不得出现与原文无关或臆造的词；不得输出解释文字；不得添加多余字段
8. 去重：同一(aspect, opinion, category, polarity)组合只保留一个
9. 排序：按opinion在原文首次出现位置升序；若相同，按aspect排序（"_"视为最大）
10. 只输出JSON，不输出其他任何文本
```

## 4. 方案优势

- **场景适配性强**：微调提供领域基础能力，RAG few-shot 提供长尾场景补充。
- **推理效率与稳定性兼顾**：BM25 轻量召回 + 本地 Reranker 精排，减少远程依赖。
- **输出质量可控**：强约束提示词 + 示例格式化 + 后处理校验（去重、排序），降低非法输出风险。
